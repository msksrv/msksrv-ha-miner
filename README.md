# MSKSRV ASIC Miner — интеграция Home Assistant для ASIC-майнеров

**Язык:** **Русский** · [English](README.en.md)

**MSKSRV ASIC Miner** — пользовательская интеграция [Home Assistant](https://www.home-assistant.io/) для локального мониторинга и управления ASIC-майнерами. Данные получаются напрямую из локальной сети через [pyasic](https://github.com/UpstreamData/pyasic); облачный сервис не требуется.

Интеграция создаёт отдельное устройство для каждого майнера (Antminer, WhatsMiner, Avalon, Innosilicon, Goldshell, IceRiver, BitAxe и другие, поддерживаемые pyasic). Несколько устройств можно объединить в **ферму** — виртуальное устройство с общей статистикой, управлением пулами, аварийным отключением и необязательной **оценкой** стоимости электроэнергии.

## Возможности

| Область | Что умеет |
|--------|-----------|
| **Обнаружение** | DHCP (имя хоста и MAC), сканирование подсети, ручной IP |
| **Майнер** | Хешрейт, температура, вентиляторы, пулы, лимит мощности, пауза майнинга |
| **Ферма** | Суммарный хешрейт и мощность, аварийное отключение, массовая смена пула, единый/двух- или трёхзонный тариф |
| **Автоматизация** | Службы и действия устройства для перезагрузки, режима работы и пулов |

Майнеры опрашиваются каждые **10 секунд**, ферма обновляется каждые **15 секунд**. При потере связи телеметрия майнера становится недоступной. Ферма продолжает обновляться и учитывает недоступных участников в оценке состояния.

## Установка

### Home Assistant 2026.11 и новее

1. Откройте **Настройки → Marketplace → Add from link**.
2. Введите `https://github.com/msksrv/msksrv-ha-miner`. При первом добавлении подключите GitHub, если Marketplace предложит это сделать.
3. Откройте **MSKSRV ASIC Miner** и установите стабильную версию. Перезапустите Home Assistant, если он предложит это сделать.

Репозитории и интеграции, ранее установленные через HACS, переносятся при обновлении Home Assistant. [Документация Marketplace](https://www.home-assistant.io/integrations/marketplace/#custom-repositories)

### Home Assistant 2026.3–2026.10 с HACS

В HACS откройте меню **⋮ → Пользовательские репозитории**. Добавьте `https://github.com/msksrv/msksrv-ha-miner` с типом **Интеграция**, затем скачайте **MSKSRV ASIC Miner** и перезапустите Home Assistant. [Документация HACS](https://www.hacs.xyz/docs/faq/custom_repositories/)

### Ручная установка и обновление

Скачайте [miner.zip](https://github.com/msksrv/msksrv-ha-miner/releases/latest/download/miner.zip) из стабильного релиза. Распакуйте содержимое архива в `config/custom_components/miner/`. Файл `manifest.json` должен находиться прямо в каталоге `miner`. При обновлении замените файлы интеграции, сохранив записи устройств в Home Assistant. Перезапустите Home Assistant.

## Настройка

Общий путь: **Настройки → Устройства и службы → Интеграции → MSKSRV ASIC Miner**.

Откройте **Настроить** у записи майнера или фермы в разделе интеграций, чтобы изменить её параметры.

### Добавление майнера

1. **Добавить интеграцию** → выберите **Сканирование**, **Вручную** или завершите поток после DHCP-обнаружения.
2. При необходимости укажите учётные данные **RPC / веб / SSH**.
3. Задайте имя устройства.

### Перенастройка (reconfigure)

На записи одиночного майнера: **Перенастроить** (часто в меню **⋯**) — IP, учётные данные, диапазон мощности. Поля пароля оставьте **пустыми**, чтобы сохранить текущие значения.

### Опции майнера

**⚙️ Настроить** на записи майнера:

- **Выключатель питания** — привязка `switch` для кнопок включения/отключения питания.
- **Источник энергии** — автоматический выбор, физический счётчик или расчёт по мощности.
- **Пороги состояния майнера** — автоматический профиль по модели, общие значения или собственные пороги.
- **Тайминг Repairs** — выдержка до появления предупреждения и время нормальной работы до его снятия.
- **Автоматическое восстановление** — перезагрузка при устойчивом падении хешрейта и опциональный цикл питания.
- **Stratum-пул** — замена основного или добавление резервного пула. Для применения настройки подтвердите действие, пока майнер доступен.

## Ферма

**Ферма** объединяет уже добавленные майнеры в одно виртуальное устройство.

1. В мастере **MSKSRV ASIC Miner** выберите **Ферма**, введите имя и добавьте майнеры. У всех участников должен быть известен один и тот же алгоритм. Если алгоритм неизвестен, дождитесь успешного опроса майнера.
2. **⚙️ Настроить** на записи фермы открывает меню:

| Пункт | Назначение |
|-------|------------|
| **Состав фермы** | Список устройств-майнеров |
| **Датчики температуры** | `sensor` с `device_class: temperature` |
| **Пулы и воркеры** | До пяти пресетов stratum |
| **Тариф электроэнергии** | Единый тариф либо два или три периода с отдельными ставками |
| **Счётчик энергии фермы** | Общий физический счётчик и опция старых датчиков стоимости |
| **Массовые действия** | Применить пресет ко всем участникам (с подтверждением) |

На каждом участнике через **⚙️ Настроить** задайте **выключатель питания** — иначе аварийная остановка для него недоступна.

**Аварийная остановка** сохраняет блокировку автовосстановления участников и выключает привязанные выключатели питания параллельно. Ошибка одного выключателя не прерывает обработку остальных.

**Массовая смена пула** блокируется, если участники сообщают **разные алгоритмы**. Операция **не транзакционна**: если отдельный майнер недоступен или отклонит настройку, пул на других участниках к этому моменту уже может быть изменён.

Интеграция оценивает **стоимость** по настроенному тарифу и приращению учтённой энергии.

После сохранения параметров фермы запись **перезагружается автоматически**.

Пароли пресетов в формах не показываются повторно; пустое поле пароля сохраняет текущее значение.

| Платформа | Назначение |
|-----------|------------|
| **sensor** | Телеметрия майнера, оценка состояния и аномалий, энергия, эффективность и качество учёта |
| **binary_sensor** | Признаки проблем с хешрейтом, температурой, платами, вентиляторами, пулом и питанием |

## Здоровье, восстановление и энергия

### Здоровье и Repairs

Оценка здоровья майнера учитывает доступные данные о хешрейте, температуре, вентиляторах, платах, пуле и ошибках. По мере накопления данных интеграция обучает эталон для текущего режима работы. Оценка фермы учитывает недоступных участников.

При устойчивой проблеме откройте **Настройки → Система → Исправления** (Repairs). Набор действий зависит от проблемы. Например, при высокой температуре можно проверить пороги, а при потере связи с участниками фермы — повторить опрос. Выдержки для майнера настраиваются в его параметрах.

### Автовосстановление и аварийная остановка

Автовосстановление выключено по умолчанию. Оно реагирует на устойчиво низкий хешрейт и сначала пробует перезагрузку майнера. Для аппаратного цикла питания отдельно включите соответствующую опцию и привяжите HA-выключатель.

Аварийная остановка фермы блокирует автоматическое восстановление её участников и выключает привязанные выключатели. Блокировка сохраняется после перезагрузки. Чтобы снять её, нажмите кнопку снятия блокировки дважды за 30 секунд. Снятие блокировки само по себе не включает питание.

### Источники энергии и панель «Энергия»

В режиме **Авто** интеграция предпочитает физический счётчик энергии, затем датчик мощности выключателя и затем мощность из телеметрии майнера. В опциях можно явно выбрать счётчик или датчик. Физический счётчик должен иметь класс `energy` и единицы Wh, kWh или MWh. Для расчёта по мощности используется датчик класса `power` с единицами W, kW или MW.

Ферма суммирует данные участников или использует собственный счётчик в разделе **Счётчик энергии фермы**. Для панели «Энергия» добавьте накопительный сенсор кВт·ч в **Отдельные устройства** (Individual devices). Если хотите показать ферму и её участников одновременно, укажите ферму как родительское устройство в настройках панели, чтобы потребление не суммировалось дважды. [Документация Home Assistant](https://www.home-assistant.io/docs/energy/individual-devices/)

### Тариф по дате и ежемесячная сводка

В настройках фермы откройте **Тариф электроэнергии → Новая цена с даты**. Укажите дату и цену для действующего тарифа. Для зонного тарифа введите цены по зонам. Дата начинается в полночь по времени Home Assistant. Чтобы применить настройки сразу или изменить тип тарифа, выберите один из трёх типов в меню. Повторное сохранение на ту же дату заменяет ставку этой даты. Ставки на другие даты сохраняются.

При вводе задним числом стоимость пересчитывается по истории накопительного счётчика фермы. Интеграция берёт подробные записи, а при их отсутствии использует непрерывную почасовую статистику. Если граница тарифа или зоны проходит между замерами, расход внутри интервала распределяется пропорционально времени. Если нет покрытия даты или счётчик в истории пошёл назад, форма покажет ошибку. Для пересчёта по дате используется одна валюта. Для периода до первой записи в расписании исходной считается ставка, которая была настроена при создании расписания.

Поправка применяется к датчикам стоимости фермы за сегодня, текущий и прошлый месяц и за всё время. Показания кВт·ч и прежние строки в «Истории» Home Assistant сохраняются.

Чтобы получать сводку первого числа, импортируйте [шаблон ежемесячной сводки](https://github.com/msksrv/msksrv-ha-miner/blob/main/blueprints/automation/msksrv/farm_monthly_summary.yaml). Выберите датчики **«Энергия за прошлый месяц»** и **«Стоимость за прошлый месяц»** одной фермы. Сводка появится в уведомлениях Home Assistant, когда оба датчика покажут данные за завершившийся месяц.

### Датчики стоимости при обновлении до 1.7

Стоимость рассчитывается по учтённой энергии и тарифу фермы. Существующие старые датчики стоимости по умолчанию отключаются. Если их используют автоматизации или карточки, переключите их на новые сущности либо включите старые датчики в разделе **Счётчик энергии фермы**. Сущности, вручную отключённые пользователем, сохраняют это состояние.

## Автоматизации

Чтобы получить `device_id`, откройте **Инструменты разработчика → Действия**, выберите действие `miner.reboot` и нужный майнер, затем переключитесь в режим YAML. Для `miner.set_farm_pool` выберите устройство фермы.

### Перезагрузка майнера

```yaml
action: miner.reboot
data:
  device_id:
    - YOUR_DEVICE_ID
```

### Смена основного пула

```yaml
action: miner.set_pool
data:
  device_id:
    - YOUR_DEVICE_ID
  mode: manual
  host: pool.example.com
  port: 3333
  use_ssl: false
  username: account.worker1
```

### Пул на всех участниках фермы

В имени воркера `{ip}` подставляет IP майнера, а `{ip_last}` — последний октет IPv4.

```yaml
action: miner.set_farm_pool
data:
  device_id:
    - FARM_DEVICE_ID
  mode: manual
  host: pool.example.com
  port: 443
  use_ssl: true
  username: user.{ip_last}
```

### Уведомление о потере связи

[Готовый шаблон уведомлений](https://github.com/msksrv/msksrv-ha-miner/blob/main/blueprints/automation/msksrv/miner_alerts.yaml) можно импортировать по URL в **Настройки → Автоматизации и сцены → Шаблоны**. Выберите майнер при создании автоматизации. Шаблон создаёт уведомления в Home Assistant о потере связи, перегреве и блокировке автовосстановления.

Интеграция публикует события майнера и фермы в шину Home Assistant как `miner_event`. Поле `type` содержит тип события, а `scope` указывает `miner` или `farm`. Карточка события показывает конкретную проблему, например «Перегрев». У сущности `event.*` атрибут `event_type` для новой проблемы имеет вид `problem_detected_temperature`, а в шине по-прежнему используется `type: problem_detected` вместе с `problem_type`. Пример срабатывает после трёх неудачных опросов майнера подряд.

```yaml
alias: Майнер недоступен
triggers:
  - trigger: event
    event_type: miner_event
    event_data:
      scope: miner
      type: offline
      device_id: YOUR_DEVICE_ID
actions:
  - action: persistent_notification.create
    data:
      title: Майнер недоступен
      message: Проверьте питание и сеть майнера.
```

### Причины событий майнера

В «Событиях» отображается тип проблемы. При открытии события доступны показания на момент срабатывания, если майнер их передал.

| Событие | Что означает и что видно в подробностях |
|---|---|
| Потеряна связь с майнером | Несколько опросов подряд завершились ошибкой. Видно их количество. |
| Проблема с хеш-платой | Плата отсутствует, не хеширует, имеет мало работающих чипов или выделяется среди других плат по хешрейту либо температуре. Видно слот и соответствующие показания. |
| Низкий хешрейт | Хешрейт ниже ожидаемого либо упал при прежнем потреблении. Видны текущий хешрейт и эталон или порог, когда они доступны. |
| Перегрев | Температура чипов или платы достигла своего порога. Видны оба показания и их пороги. |
| Проблема с вентилятором | Обороты ниже порога или один вентилятор заметно медленнее остальных. Видны индекс, обороты и порог либо медиана. |
| Проблема с пулом | Пул недоступен, не выдаёт задания, растёт доля устаревших шар или давно не было принятых шар. Видны состояние пула, ошибки и доступные показатели шар. |
| Много отклонённых шар | Доля отклонённых шар превысила порог или выросла относительно эталона. Видны доля и доступные счётчики. |
| Необычная потребляемая мощность | Мощность вышла за диапазон, рассчитанный по эталону или лимиту майнера. Видны мощность и границы диапазона. |
| Медленное восстановление после перезагрузки | Хешрейт не вернулся к эталону вовремя. Видны текущий хешрейт, эталон и доля восстановления. |
| Автовосстановление не удалось | Разрешённые попытки исчерпаны. Видны счётчики перезагрузок и циклов питания, а также доступные показатели хешрейта. |
| Не удалось восстановить питание | Интеграция не подтвердила включение реле после цикла питания. Видны привязанный выключатель и число неудачных попыток. |

## Действия

| Действие | Описание |
|--------|----------|
| **`miner.reboot`** | Перезагрузка |
| **`miner.restart_backend`** | Перезапуск процесса майнинга |
| **`miner.set_work_mode`** | `low` / `normal` / `high` |
| **`miner.set_pool`** | `existing` поднимает существующий пул по индексу с нуля, `manual` заменяет основной, `append` добавляет резервный |
| **`miner.set_farm_pool`** | `manual` или `append` для всех участников фермы. Укажите хост и порт |

**`miner.set_farm_pool`**: при разных алгоритмах у участников операция не выполняется. При частичном сбое (офлайн, отказ прошивки) часть майнеров может уже получить новый пул — см. [Ферма](#ферма).

Для пулов используйте вызов действия `miner.set_pool` или `miner.set_farm_pool`. В списке действий устройства доступны перезагрузка, перезапуск процесса майнинга и режим работы.

## Обнаружение

DHCP сопоставляет **имена хостов в нижнем регистре** (`whatsminer*`, `antminer*`…) и известные **MAC OUI** (Bitmain `E0A509`, WhatsMiner `C41025` / `C80831`). При DHCP-обнаружении интеграция пытается опознать майнер через API до трёх раз с таймаутом 6 секунд на попытку. Ручное сканирование принимает IPv4-подсеть размером до 1024 адресов. Интеграция пропускает уже настроенные устройства.

## Требования

- **Home Assistant** 2026.3.0 и новее. Релиз интеграции 1.7.0 проверен на Core 2026.3.0 и 2026.11.0 с эмулятором Bitaxe.
- **pyasic** `0.78.x` — устанавливается Home Assistant автоматически (`manifest.json`: `pyasic>=0.78.9,<0.79`).

Если в журнале **`Requirements for miner not found`**: проверьте доступ Home Assistant к **PyPI** и совместимость версии Python. Если ошибка сохраняется, приложите к [issue](https://github.com/msksrv/msksrv-ha-miner/issues) полный журнал установки.

## Безопасность

- Пароли майнеров (RPC, веб, SSH) и пулов хранятся в конфигурации Home Assistant.
- Пресеты пулов и их пароли попадают в **резервные копии** — защищайте бэкапы.
- API майнеров предназначен для локальной сети; не публикуйте их в интернет без необходимости.

## Устранение неполадок

| Симптом | Что проверить |
|---------|----------------|
| Майнер недоступен | Ping, пароли, файрвол, веб-интерфейс с хоста HA |
| Нет датчиков стоимости у фермы | Тариф в **⚙️ Настроить**; для зон — валюта и положительные цены во всех зонах |
| Массовая смена пула срывается | Журнал `Farm stratum:` — офлайн, разные алгоритмы, неверный пресет |
| DHCP не срабатывает | Откройте обнаруженные интеграции. Если майнер не найден, запустите сканирование IPv4-подсети или введите IP вручную |
| Ошибка установки pyasic | Сеть, прокси, Python; см. [Требования](#требования) |

## Сообщить об ошибке

[GitHub Issues](https://github.com/msksrv/msksrv-ha-miner/issues) — приложите:

1. Версию Home Assistant  
2. Версию интеграции из Marketplace, HACS или `custom_components/miner/manifest.json`
3. Модель и прошивку майнера  
4. Версию pyasic (журнал загрузки)  
5. Шаги воспроизведения и фрагмент журнала с ошибкой. Удалите из журнала пароли и учётные данные пулов.
6. Начиная с 1.7.1 можно приложить файл **Скачать диагностику** из меню записи майнера или фермы. Выгрузка содержит состояние и телеметрию из ограниченного набора полей. Адреса, пароли и настройки пулов в неё не входят.

## Ограничения

- Набор сущностей и управление зависят от **pyasic** и прошивки конкретной модели.
- **Стоимость** — оценка по тарифу и учтённой энергии. При расчёте по мощности пропуски опроса могут уменьшить учтённое потребление.
- Отключение питания — только через привязанный HA `switch`, не через API отключения на стороне майнера.

Поддерживаемые типы устройств: [документация pyasic](https://pyasic.readthedocs.io/en/latest/miners/supported_types/).
